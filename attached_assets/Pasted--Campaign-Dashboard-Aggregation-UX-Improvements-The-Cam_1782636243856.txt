# Campaign Dashboard Aggregation & UX Improvements

The Campaign dashboard is currently not synchronized with the underlying Batch data.

Example:

Campaign Dashboard

Booked = 0

↓

Open Batch B8

Booked = 1

This should never happen.

A Campaign is simply a collection of Batches.

Therefore every Campaign metric must always be computed from all of its Batches.

---

# Required Architecture Change

The Campaign page should NOT maintain its own statistics.

Instead, it should aggregate all Batch metrics.

Conceptually:

Campaign Stats

=

SUM(Batch 1)

+

SUM(Batch 2)

+

SUM(Batch 3)

+

...

+

SUM(Batch N)

There must be a single source of truth.

Batch is the source of truth.

Campaign is an aggregated view.

Never store duplicate counters.

---

# Backend Changes

Implement a centralized aggregation service.

CampaignStatsService

Responsibilities:

- Aggregate statistics from all batches.
- Compute campaign totals in real time.
- Emit updates whenever a batch changes.
- Prevent duplicated counters.
- Provide a single source of truth.

All pages should consume this service instead of maintaining independent counters.

---

# Performance

Do not recalculate everything on every page load.

Instead:

- Incrementally update aggregates when a lead outcome changes.
- Cache campaign aggregates.
- Invalidate only the affected campaign when a batch updates.

This ensures scalability for campaigns containing thousands of batches and hundreds of thousands of leads.

---

# Goal

The Campaign Dashboard must always represent the real-time aggregated state of all batches.

Users should never see different numbers between:

Campaign Dashboard

↓

Batch Overview

↓

Lead Table

↓

Analytics

All views must stay synchronized using a single source of truth.
