# SnapServe AI – Agent Draft History & Version Control System

## Objective

Implement a complete Git-like version control system for AI Agents.

Current behavior:

* Versions are only created on Publish.
* Users can lose working configurations if they save multiple times and later want to restore an earlier state.

New behavior:

* Every Save automatically creates a Draft Snapshot.
* Every Publish creates a Published Version.
* Users can compare any two snapshots or versions.
* Users can restore any snapshot or version at any time.
* No existing agent execution, voice infrastructure, tools, memory, scheduling, CRM, analytics, or publishing behavior should be changed.

---

# Core Concepts

## Draft Snapshots

Create a snapshot automatically every time the user clicks Save.

Examples:

Draft Snapshot #1
Draft Snapshot #2
Draft Snapshot #3

Metadata:

* Snapshot ID
* Agent ID
* Created By
* Timestamp
* Change Summary
* Snapshot Type = Draft
* Full Agent Configuration JSON

---

## Published Versions

Create only when Publish is clicked.

Examples:

V1 Published
V2 Published
V3 Published

Metadata:

* Version Number
* Agent ID
* Published By
* Published Timestamp
* Change Summary
* Full Agent Configuration JSON

# Restore Feature

When Restore is clicked:

DO NOT overwrite immediately.

Show modal:

Restore Snapshot

This will create a new Draft Snapshot from the selected version.

Current configuration will remain recoverable.

Buttons:

Cancel

Restore

---

Restore Process

Selected Snapshot
→ Create New Snapshot
→ Make Current Working Draft

This ensures no data is ever lost.

# Retention Policy

Draft Snapshots

Keep latest 100 snapshots.

Auto-delete oldest snapshots after 100.

Published Versions

Never delete automatically.

User can archive manually.

---

# Restore Last Working Version

Existing button:

Restore Last Working Version

Restore latest published version as a new draft snapshot.
