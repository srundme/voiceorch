1. lastFrameWasLoud as a single boolean is wrong. Think about when onFinal fires: Sarvam finalizes a segment after it sees end-of-speech silence. So between the caller's loud words and the transcript firing, there are silence frames — and your boolean gets overwritten to false by them. By the time isAgentEcho reads it, it reflects the trailing silence, not the utterance. Your short-confirmation tiebreaker (size <= 2 && energyWasFull → accept as caller) would then fail on exactly the case it exists for. Track a timestamp instead:
typescript// in audio path, before any return:
if (rms > BARGE_IN_RMS) lastLoudFrameAt = Date.now();

// in isAgentEcho:
const energyWasFull = (Date.now() - lastLoudFrameAt) < ECHO_CONTENT_WINDOW_MS;
2. Don't delete ECHO_DISCARD_OVERLAP_MS / BARGE_IN_END_GRACE_MS until you grep every usage. Their names suggest the onFinal discard guard isn't the only consumer — ECHO_DISCARD_OVERLAP_MS ("speech within this of agent ending = genuine overlap") sounds like it may also be used in the barge-in path to accept real overlapping speech. If so, deleting the constant kills genuine-overlap acceptance, not just echo discard. Confirm both are only referenced in the two places you're replacing.
3. Keep the sentence-start echoGraceUntil; only retire the tail extension. Point 1/4 should not touch BARGE_IN_ECHO_GRACE_MS — that's the during-TTS barge-in suppression while browser AEC adapts, a different mechanism from the post-speech tail. Retire only echoGraceUntil = max(..., now + 400ms) after the last sentence. If you remove the start-of-sentence set too, you reopen false barge-in (constraint 3).
4. isAgentEcho must also gate the speaking (barge-in) branch, not just the post-speech else-branch. Constraint 3 is "no false barge-in from echo." If point 4 only swaps the discard in the non-speaking path, the agent can still be interrupted by its own loud echo mid-sentence during the AEC-adaptation window. Both branches of onFinal need the content check.
5. Normalize and strip SSML before pushing to recentAgentText. You feed Cartesia SSML-formatted text. If the buffer stores raw <break>/prosody markup, token matching silently never hits and every echo leaks through. Push the plain spoken text, NFC-normalized with ZWJ/ZWNJ stripped — same pipeline as the transcript side, or "சரி" won't match "சரி" across TTS-input vs STT-output encodings. Also prune the buffer on push (drop entries older than AGENT_TEXT_BUFFER_MS) so it doesn't grow over a long call. Watch the Hinglish case specifically: if TTS input is Latin-script but Sarvam returns Devanagari, containment is zero — you may need a transliterated comparison key for those tenants.
6. Explicitly regression-test the original self-echo bug. The entire reason inEndGrace existed (Concern A) was the agent responding to its own "சரி." Removing the audio block means content matching is now the only thing standing between you and that bug. Test it directly: agent says a 1-word confirmation, verify it doesn't loop. This is also where your point-1 tiebreaker is riskiest — a loud echo before AEC adapts is both short and high-energy, so it can slip through as "caller." That's an acceptable tradeoff (dropped-genuine happens every turn; this is rare and recoverable) but you want to know its failure shape before a customer does.
