Build an "Execution Logs" feature similar to Bolna AI for our Voice AI Orchestration Platform.

## Objective

Create a complete execution logging and debugging system that records every step of the AI conversation pipeline.

The purpose of this feature is to help developers, QA teams, and customers understand:

1. What was sent to the LLM.
2. What the LLM responded with.
3. What the STT provider returned.
4. What was sent to the TTS provider.
5. What tools were called.
6. What variables were injected.
7. Whether memory/context was correctly passed.
8. Whether prompts are behaving as expected.

This feature should act as a "Conversation Debugger".

--------------------------------------------------

## Why this feature is important

When building Voice AI agents, debugging is difficult because users only hear the final voice output.

Developers need visibility into:

- STT input
- STT output
- Prompt construction
- Variable replacement
- Memory injection
- LLM request
- LLM response
- Tool execution
- TTS request
- TTS response

Example:

Agent Prompt:

Hello {first_name}, how can I help you?

Variables:

{
  "first_name": "Gopi"
}

What is actually sent to the LLM:

Hello Gopi, how can I help you?

Developers must be able to verify that:

- Variables were replaced correctly
- Memory was injected correctly
- Tool outputs were injected correctly
- Prompt templates are functioning correctly

This greatly reduces debugging time.

## Backend Requirements

Every pipeline step must emit an event.

Example:

logExecution({
  callId,
  component: "LLM",
  provider: "OpenAI",
  direction: "request",
  payload: resolvedPrompt
})

logExecution({
  callId,
  component: "LLM",
  provider: "OpenAI",
  direction: "response",
  payload: llmResponse
})

Do this for:

- STT Request
- STT Response
- Variable Resolution
- Memory Retrieval
- Knowledge Retrieval
- LLM Request
- LLM Response
- Tool Request
- Tool Response
- TTS Request
- TTS Response
- Webhook Request
- Webhook Response

## Success Criteria

A developer should be able to open a call and answer:

1. What did the user say?
2. What did STT return?
3. What exact prompt was sent to the LLM?
4. Were variables correctly replaced?
5. Was memory injected?
6. Was knowledge injected?
7. Which tools were executed?
8. What did the tools return?
9. What text was sent to TTS?
10. Why did the AI respond the way it did?

The Execution Logs page should become the primary debugging console for the entire Voice AI orchestration platform.
