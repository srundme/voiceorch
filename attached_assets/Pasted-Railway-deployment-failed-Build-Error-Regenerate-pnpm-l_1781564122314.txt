## Problem

The @workspace/api-server service fails at the BUILD_IMAGE stage. The Dockerfile runs `pnpm install --frozen-lockfile` in both the builder stage (step 12/17) and the production stage (step 10/13). Both exit with:

```
ERR_PNPM_OUTDATED_LOCKFILE  Cannot install with "frozen-lockfile" because pnpm-lock.yaml is not up to date with <ROOT>/artifacts/dashboard/package.json

Failure reason:
specifiers in the lockfile don't match specifiers in package.json:
* 1 dependencies were removed: gsap@^3.15.0
```

The service config is read from /artifacts/api-server/railway.json (DOCKERFILE builder). The watchPatterns config is set to `["/artifacts/api-server/**"]`.

## Diagnosis

The `gsap@^3.15.0` dependency was removed from `artifacts/dashboard/package.json` in a prior commit, but `pnpm-lock.yaml` at the repo root was never regenerated. The `--frozen-lockfile` flag enforces strict lockfile-to-package.json consistency and rejects any mismatch.

A previous fix attempt (commit 67249edc, message: "fix: regenerate pnpm-lock.yaml — remove stale gsap entry") shows 0 files changed in its diff, meaning the lockfile was not actually modified. That deployment was also SKIPPED because the watchPatterns setting does not match root-level files. The current failing commit (7130244e) only changed a comment in artifacts/api-server/src/index.ts and did not update the lockfile.

## Fix

This fix cannot be implemented by a code agent because it requires running `pnpm install` to regenerate the binary lockfile. The user must:

1. Run `pnpm install` at the repo root locally.
2. Verify that `pnpm-lock.yaml` has changed (the gsap entries should be removed from the artifacts/dashboard workspace section).
3. Commit the updated `pnpm-lock.yaml`. To ensure the deployment is not skipped by watchPatterns, also include a trivial change to any file under `artifacts/api-server/` (e.g., update a comment in `artifacts/api-server/src/index.ts`) in the same commit.
4. Push to main. Alternatively, after pushing the lockfile fix, trigger a manual redeploy from the Railway dashboard.
