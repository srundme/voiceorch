STEP 1 — TWO-TIMER SAFETY NET (not one)
Implement two independent, env-configurable timers. A single timeout is wrong — one case needs a tight response, the other a loose backstop.

  A) FORCE-FINALIZE TIMER (common case: partials arriving, no final)
     - Arm when the FIRST non-empty partial of the current turn arrives.
     - Reset on each subsequent non-empty partial (it tracks silence-since-last-partial).
     - If it expires (no new partial and no final within the window): force-close the turn using the best available partial as the transcript, then invoke the LLM exactly as a real final would.
     - Env constant, e.g. FORCE_FINALIZE_MS, default 1800 (tune: above adaptive computeEndpointMs ceiling, well below carrier drop).
     - GUARD: only force-finalize if the best partial is non-empty after trim. If empty, do NOT send it to the LLM — fall through to the stall path (B).

  B) STALL BACKSTOP TIMER (degenerate case: no usable transcript at all)
     - Arm at turn start (when we enter "Listening…").
     - Cleared by a real STT final OR a successful force-finalize.
     - If it expires with no usable transcript: do NOT inject garbage. Instead emit a recovery reprompt ("Sorry, I didn't catch that — could you say that again?", language-aware if a language is set), reset turn state, and re-enter Listening. Do NOT hang up — on outbound insurance calls a hangup is a lost lead.
     - Env constant, e.g. STALL_BACKSTOP_MS, default 15000.
     - Hard ceiling: if the stall reprompt has already fired N times (env, default 2) with still no usable transcript, THEN end the call via the existing inactivity path.

  - Both timers must be cleared correctly on: real STT final, barge-in, and turn completion. No timer leaks across turns. Verify cleanup on every exit path.
  - Implement in BOTH pipeline.ts and webcall.ts. Keep the shared logic in endpointing.ts if it fits the existing structure; do not duplicate it in two places if it can live in the shared module.
