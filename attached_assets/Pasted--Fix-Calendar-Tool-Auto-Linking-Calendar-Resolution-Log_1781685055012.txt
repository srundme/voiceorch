# Current Product Design

SnapServe uses an INTERNAL Calendar System.

Unlike Retell AI + Cal.com:

We DO NOT want users manually entering:

- API Keys
- Event Type IDs
- Calendar IDs

Those are implementation details.

The platform should manage them automatically.

---

# Expected Architecture

Every Agent automatically has ONE SnapServe Calendar.

Example:

Agent:
Health Insurance Agent

↓

SnapServe Calendar:
Health Insurance Calendar

---

Agent:
Dental Clinic Agent

↓

SnapServe Calendar:
Dental Clinic Calendar

---

Agent:
Real Estate Agent

↓

SnapServe Calendar:
Real Estate Calendar

---

This relationship already exists inside Settings → Calendar.

The calendar is already linked to the agent.

Therefore the tools should automatically know which calendar to use.

The user should NOT need to manually select a calendar again inside tools.

# Calendar Resolution Logic

The booking tools should resolve calendars automatically.

Pseudo Flow:

Current Agent

↓

Find Agent Calendar

↓

Load Calendar Configuration

↓

Load Connected Google Account(s)

↓

Load Event Types

↓

Populate Tool Settings

# Multiple Google Account Support

Critical Requirement

One SnapServe Calendar may have multiple Google Accounts connected.

Example:

Sales Team Calendar

Connected Accounts:

sales@company.com

appointments@company.com

manager@company.com

---

The tool should NOT require manual API configuration.

The Calendar should decide which Google account handles bookings.
