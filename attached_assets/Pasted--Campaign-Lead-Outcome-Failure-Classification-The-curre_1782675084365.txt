# Campaign Lead Outcome & Failure Classification

The current Campaign > Batch > Leads page is not capturing the actual reason why a lead did not progress.

Currently we only show generic values like:

- Failed
- Busy
- No Contact

This is insufficient for businesses running outbound campaigns.

A business owner needs to know WHY every lead failed so they can decide whether to retry, schedule callbacks, or remove the lead.

---

# Introduce Failure Classification

Every completed call must be assigned ONE standardized failure reason.

Example categories:

## Customer Related

• No Answer
• Busy
• Call Rejected
• Switched Off
• Invalid Number
• Number Does Not Exist
• Voicemail
• DND Blocked
• Wrong Number

---

## Telephony Related

• Carrier Failure
• SIP Failure
• Network Error
• Telephony Timeout
• Provider Error
• Call Dropped
• Failed to Connect

---

## AI Related

• LLM Timeout
• STT Failure
• TTS Failure
• Tool Execution Failed
• Agent Crash
• Context Window Exceeded

---

## Platform Related

• Insufficient Wallet Balance
• Campaign Paused
• Batch Stopped
• Rate Limited
• API Failure

---

## User Related

• Requested Callback
• Requested Human Agent

• Asked to Call Later
• Wrong Timing

# Callback Handling

If during the conversation the user says:

"Call me later."

"Can you call tomorrow?"

"I'm driving."

"I'm busy."

"Call after 6 PM."

"Call next Monday."

The AI should NOT mark the call as Failed.

Instead:

Outcome

Callback Requested

The lead should automatically move into the Callback queue.

# Automatic Callback Detection

The platform should detect callback intent automatically.

Examples:

"I'll talk later."

"Call me after lunch."

"Can you ring me tomorrow?"

"I'm in a meeting."

"Call after 7."

"Please call next week."

The AI should classify these as:

Outcome

Callback Requested

instead of Failed.

Yes

No

DND

Requested Callback

# Source of Truth

Failure reasons should not be guessed from the final call outcome.

They should be derived from:

Telephony Provider Events

Voice Pipeline Events

Tool Execution Logs

LLM Events

Conversation Analysis

Platform Events

and stored as a normalized failure reason.

---

# Goal

Every lead should clearly answer these questions:

What happened?

Why did it happen?

Can it be retried?

When should it be retried?

Did the customer ask for a callback?

Should it appear in the Callback queue?

The Campaign module should provide enough operational insight that a business owner never has to open the call logs just to understand why a lead failed.
