PHASE 1B — BATCH WIZARD IMPLEMENTATION SPECIFICATION

Status: Approved
Architecture Version: v1.2
Prerequisite: Phase 1A Complete ✅

Objective:

Build the Batch Wizard as a lead onboarding pipeline.

This is NOT a generic form builder.

This is the primary entry point through which all leads enter the SnapServe operational system.

Every future queue, CRM record, callback, booking, transfer, interaction, analytics event, and command center metric originates from a batch.

The wizard must therefore focus on:

Lead Ingestion
Lead Validation
Variable Mapping
Duplicate Handling
Execution Configuration

not configuration complexity.

## NON-NEGOTIABLE UX RULES

1. Wizard must be linear.

No giant form.

2. User always knows:

Where they are.

What happens next.

3. Validation must happen before launch.

Never after.

4. Every error must be actionable.

No generic messages.

5. Required variables always visible.

6. Duplicate policy must be explicit.

7. Phone normalization preview must be visible.

8. Import summary must be visible.

9. Every import creates batch_import_run.

10. Source reuse must be first-class.

Most customers will reuse sources.

Optimize for reuse.
