## Problem
The `@workspace/api-server` service fails at the BUILD stage. The Dockerfile builds both the dashboard and api-server in a multi-stage build. During step 16/17 (`pnpm --filter @workspace/dashboard run build`), Vite/Rollup exits with:
```
"useArchiveAgentVersion" is not exported by "../../lib/api-client-react/src/index.ts", imported by "src/pages/agents/builder.tsx"
```
The builder is DOCKERFILE, config comes from `artifacts/api-server/railway.json` which sets `build.dockerfilePath: "Dockerfile"`. SNAPSHOT succeeded; BUILD failed. No changes have been pushed to `main` after this commit.

## Diagnosis
The API client at `lib/api-client-react/src/generated/api.ts` is generated by Orval from the OpenAPI spec at `lib/api-spec/openapi.yaml`. The `useArchiveAgentVersion` hook was never generated because the corresponding endpoint (e.g., `PATCH /api/agents/{id}/versions/{versionId}/archive`) does not exist in the OpenAPI spec. The commit `4d667dd` attempted to fix this by adding schema types to `api.schemas.ts`, but schemas alone do not generate hooks — the endpoint definition in the OpenAPI spec is required. The `builder.tsx` file (207KB) imports `useArchiveAgentVersion` on line 26 and likely uses it in the Versions tab UI. The previous deployment `6836b99c` failed with the identical error.

## Fix
Two options (both require manual steps):

**Option A — Add the endpoint to the OpenAPI spec and regenerate (preferred):**
1. File: `lib/api-spec/openapi.yaml` — add the `archiveAgentVersion` endpoint definition (e.g., `PATCH /api/agents/{id}/versions/{versionId}/archive`) with appropriate request/response schemas referencing the `AgentVersion` type.
2. Run `pnpm orval` (or the project's codegen script) to regenerate `lib/api-client-react/src/generated/api.ts` — this will produce the `useArchiveAgentVersion` hook.
3. Commit both the updated OpenAPI spec and the regenerated `api.ts`.

**Option B — Remove the import and usages (if the feature is not ready):**
