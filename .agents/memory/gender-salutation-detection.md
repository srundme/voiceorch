---
name: Caller gender salutation detection
description: Why caller Sir/Ma'am salutation silently fails and the invariants that keep it working on web + telephony
---

Caller gender detection (the `{caller_salutation}` → "Sir"/"Ma'am" feature) is fragile in three non-obvious ways. All three must hold or the salutation silently never appears.

**1. Production URL topology.** On Railway the api-server and the Voice Analysis (gender) microservice run in SEPARATE containers. The detectors default to `http://localhost:5000`, which only works in single-VM dev. Prod MUST set `GENDER_SERVICE_URL=http://gender-service.railway.internal:5000` (documented in MIGRATION_RUNBOOK.md / .env.example) or every detection fetch fails and gender resolves null for the whole call.
**Why:** a null gender + a null-branch directive means the agent greets everyone neutrally — looks like a prompt bug but is really env misconfig.
**How to apply:** the startup probe (`orchestration/genderService.ts → probeGenderService`, called from index.ts listen) logs the resolved URL + reachability loudly. Check that log first when salutation is missing in prod. All three detectors resolve the base via the shared `genderServiceBaseUrl()`.

**2. Arming invariant — sample the caller's INTRO, not the greeting.** The detector must only be fed audio AFTER the agent greeting is delivered, so it samples the caller's introduction turn. Audio feed is gated on `genderDetectionArmed`; `armGenderDetection()` is called in greet()'s `finally` (after greeting drained) and in the `firstSpeaker === "user"` early-return branch.
**Why:** feeding pre-greeting / greeting-echo audio pollutes the 2s sample window and the v0 detector auto-fires once at 2s — a bad early sample locks in a wrong/null result.
**How to apply:** this lives in the SHARED pipeline core (createSession/pipeline.ts), so web calls and telephony both inherit it. Never re-implement in webcall.ts.

**3. Gate on placeholder + toggle; directive must be verbatim.** Only instantiate a detector when `genderDetectionEnabled && systemPrompt contains {caller_salutation}` — otherwise we waste gender-service calls for nothing. **OFF must mean off, in three places:** (a) the toggle's missing-field default is OFF (`?? false` in session config resolution — must match the dashboard/admin UI display default; it was `?? true` for a while, so older agents showed OFF but ran ON); (b) a stored `gender` fact in caller memory must be suppressed from the injected KNOWN DETAILS block when the toggle is off (`injectEnhancedMemory` `suppressGenderFact` opt) or the LLM keeps saying Sir/Ma'am from memory captured during detection-ON calls — the DB row is kept so flipping ON restores it; (c) the vibe agent-creation flow must persist the toggle explicitly (true AND false), never only-when-true. The per-turn `[CALLER GENDER — MANDATORY]` directive is appended AFTER the language guard (recency) and tells the LLM to keep the salutation EXACTLY as written / as a proper noun that overrides the language rule.
**Why:** see language-rule-proper-nouns — the strict single-language rule transliterates "Sir"/"Ma'am" otherwise; and a soft "when appropriate" directive made weak LLMs drop it entirely.

**4. Detection strategy = wav2vec2-primary ordered fallback chain (single class).** The detector is now always `GenderDetectorChained` (the old per-provider GenderDetector/ML/MLv2 selection by `genderDetectionProvider` is bypassed — config kept only for back-compat). Each `runDetection()` POSTs the accumulated WAV to three endpoints IN ORDER with a 1.5s timeout each: `/voice-analysis/gender-ml-v2` (wav2vec2) → `/voice-analysis/gender-ml` (autocorrelation) → `/voice-analysis/gender` (pitch). First result with gender∈{male,female} AND confidence≥0.75 wins and LOCKS for the call; on timeout/low-confidence it falls through; if none qualify it keeps neutral and retries next turn (no sub-threshold lock, unlike the old detectors' enough_audio fallback). Buffer capped at MAX_BYTES (~10s, keeps most recent) so a never-locking call can't grow unbounded.

**5. The greeting-LLM path is a separate substitution site — easy to miss.** `{caller_salutation}` is resolved in THREE places in pipeline.ts, all via the shared `salutationFor(gender)`/`substituteSalutation(text,sal)` helpers: (a) static greeting, (b) the greeting-LLM **system prompt** (was the GAP — `this.agent.systemPrompt` still carries the raw placeholder because session.ts/prompt-vars.ts skip it; sending it raw made the opener LLM echo the literal token), (c) per-turn in processTurn. greeting paths resolve to NEUTRAL (detection hasn't fired yet).

**6b. Diagnose without placing a call + loud-on-failure.** `GET /api/admin/gender-service/diagnostics` (requireAdmin, `x-admin-token`) probes /health, /ready, and all 3 detection endpoints with a 1s silent WAV and returns `{resolvedUrl, configured, summary:{healthy,ready,anyDetectionResponds,ok}}` — use this to confirm prod wiring without a real call. Cold wav2vec2 first-hit can take ~10s, so the diagnostic probe timeouts are generous (25s). Runtime: when EVERY model in the chain fails in a turn (service unreachable), `genderDetectorChained` emits ONE rate-limited (60s window, process-wide) warn with the resolved URL + reason instead of a silent neutral fall-through — grep that line when salutation is missing in prod.

**7. Explicit caller correction override.** `effectiveGender() = salutationCorrection ?? genderDetector.gender`. `detectSalutationCorrection(transcript)` runs each turn and, when matched, sets sticky `salutationCorrection` that overrides even a locked detection. Belt-and-suspenders: the MANDATORY directive also carries an EXCEPTION clause so a phrasing the regex misses is still honored by the LLM.
**Indic word order is the trap.** English/romanized-Hindi negate BEFORE the word ("not ma'am"); Tamil/Hindi negate AFTER ("ma'am illa", "sir nahi", "ma'am mat", "ma'am vendaam") and the negator often arrives in NATIVE SCRIPT (இல்ல/இல்லை, வேண்டாம், नहीं, मत) even when "ma'am"/"sir" stay Latin. So the detector needs separate postfix-negation regexes (salutation + short gap + negator, negator allowed in script), and those must be checked BEFORE the prefix regexes — otherwise "mujhe ma'am mat bolo" ("don't call me ma'am" → male) matches the "call me ma'am" (mujhe ma'am → female) prefix first and flips the wrong way. An objection to a salutation maps to the OPPOSITE gender. Romanized negators carry a trailing `(?![a-z])` so "illadhu" etc. don't false-trigger.
**Why the apology was backwards:** when the regex missed the correction, the per-turn directive kept hard-asserting the wrong gender, and the LLM tried to reconcile the caller's objection with a mandatory contradictory instruction → garbled "Sorry, I thought you were male, I'll call you that" while still using the wrong salutation. Fix is both: capture the correction (so effectiveGender flips the directive) AND a strengthened EXCEPTION clause forbidding the model from naming/guessing any previously-assumed gender when it switches.
